# プラン: 撮影日時の順に並べ、撮影日ごとに見出しを入れる

元資料: `docs/requirements/date-headings.md`

## 決定事項(確認事項はすべて推奨案で決めた)

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| Q1 | 撮影日時の取り方 | ファイル名から、正規表現 `(\d{8})[_-](\d{6})` の最初の一致で読む。日付・時刻として正しくなければ読めないものとする | ユーザーの動画(`20250804_184201.mp4`)と、よくあるスマホの名前(`VID_…`、`PXL_…`)の両方に合う。メタデータを読むにはサーバーの変更が要り、今回はファイル名で足りる |
| Q2 | 見出しの文 | 「2025年8月4日」(月・日は0で埋めない)、表示時間1秒 | 読みやすく、日本語を表示できる。表示時間はテキストの場面の初期値と同じ |
| Q3 | 並べるときの見出し | すぐ後ろの動画の見出しとして一緒に動かす。最後の動画より後ろの見出しは末尾のまま | 手で入れた見出しを消さず、意味(どの動画の見出しか)を保つ |
| Q4 | 読めない動画 | 末尾に元の順のまま。見出しは付けない | 推測で並べない |
| Q5 | 2回押したとき・あとから動画を足したとき | 日付の見出しは「その日の見出し」として扱う。既にある見出しは作り直さずにその日の最初の動画の前へ移し(表示時間・id は保つ)、同じ日付の見出しは1つにまとめる。「撮影日時の順に並べる」も、既にある日付の見出しを置き直す(新しくは作らない)。処理は `placeDateHeadings.ts` にまとめる | 実装レビュー P1: 当初の「直前のかたまりに同じ文があれば入れない」では、見出しを入れたあとに同じ日の早い動画を足して並べ直すと、見出しが日の途中に残り、もう一度押すと同じ見出しが2つになった |
| Q6 | ボタンの置き場所 | 結合リストの上、「先頭にテキストを挿入」の隣 | 一覧の操作の近く |
| Q7 | 出力のファイル名の指定 | 今回は扱わない | ダウンロード後に名前を変えられる |
| Q8 | レビュー | 実装後に1つのサブエージェントで、プランとの照合・異常系・セキュリティの3観点をまとめて見る | 画面だけの小さな変更のため |

## 1. 概要

結合リストの上に「撮影日時の順に並べる」「撮影日ごとに見出しを入れる」の2つのボタンを足す。サーバーは変えない。

## 2. 背景

プロトタイプで行っていた月ごとの作業(撮影日時の順に並べ、日付の見出しを挟む)を、今のアプリでは手でやる必要がある(要件の背景)。

## 3. 詳細設計

### 純粋関数(`frontend/src/features/merge/`)
- **`parseShootingDateTime.ts`**: `(fileName) => { date: "20250804"; key: "20250804184201" } | null`
- **`formatDateHeading.ts`**: `("20250804") => "2025年8月4日"`
- **`sortByShootingDateTime.ts`**: `(items) => MergeItem[]`。テキストの場面を後ろの動画とまとめた「かたまり」を作り、動画の撮影日時のキーで安定に並べる(読めないものは後ろ)。末尾の見出しは最後に残す。並べたあと `placeDateHeadings(…, null)` で、既にある日付の見出しをその日の最初の動画の前へ置き直す(新しくは作らない。同じ日付の見出しは、並べたあとの順で最初の1つにまとめる)
- **`insertDateHeadings.ts`**: `(items, nextId: () => string) => MergeItem[]`。`placeDateHeadings(items, nextId)` を呼ぶ
- **`placeDateHeadings.ts`**(実装レビューで追加): 日付の見出しを「その日の見出し」として置き直す。動画に出てくる撮影日と同じ文のテキストの場面を日付の見出しとみなし、同じ日付は最初の1つ(id・表示時間はそのまま)にまとめ、撮影日が変わる位置(その日の最初の動画の直前に続く、日付の形でないテキストの場面のかたまりの前)に置く。nextId を渡したときだけ、見出しのない日に新しく作る。日付の形の見出しはまたがない(その日の動画を全部消して残った見出しと、次の日の見出しが入れ替わらないため)

### 状態(`useMergeQueue.ts`)
- `sortByShootingTime()`、`insertDateHeadings()` を足す。入力欄が開いている間は何もしない。関数で更新する。見出しの id は既存のテキストの場面と同じ `text-N` の数え方

### 画面
- `MergeOrderList.tsx` の「先頭にテキストを挿入」の並びに、2つのボタンを足す(`disabled`: ロック中・動画なし)。props に `onSortByShootingTime`・`onInsertDateHeadings`
- `App.tsx` で配線する。`MergeOrderList` が受け取る動画の有無は `items` から判断する

## 5. 新規テストケース

### 単体
- `parseShootingDateTime`: `20250804_184201.mp4` → 20250804 / 20250804184201。`VID_20250804_184201.mp4`、`PXL_20250804_184201123.mp4`、`20250804-184201.mp4` も読める。`clip.mp4`、`20251304_184201.mp4`(13月)、`20250230_120000.mp4`(2月30日)、`20250804_256000.mp4`(25時)は null
- `formatDateHeading`: 20250804 → 「2025年8月4日」、20251231 → 「2025年12月31日」
- `sortByShootingDateTime`: 受け入れシナリオの3本の並べ替え。見出しが後ろの動画と一緒に動く。末尾の見出しは末尾のまま。読めない動画は後ろに元の順。同じ撮影日時は元の順。元の配列を変えない。空・動画なし
- `insertDateHeadings`: 受け入れシナリオ(2日分で見出し2つ、表示時間10)。2回目は増えない(同じ並び)。読めない動画には付けない。読めない動画を挟んでも、日付が同じなら見出しは増えない。手で入れた別の文の見出しが直前にあっても、日付の見出しは入れる(その前に。ただし手で入れた文が日付の形なら、またがずにその後ろに入れる)。日の途中に取り残された見出しは、その日の最初の動画の前へ移す(id・表示時間を保つ)。同じ日付の見出しは1つにまとめる。その日の動画を全部消して残った見出しは、次の日の見出しと入れ替わらない。元の配列を変えない。id は渡した関数から取る
- `useMergeQueue`: 2つの操作が並びを変える。入力欄が開いている間は何もしない。見出しの id が text-N の続き番号。画面に反映される前に追加された動画を上書きしない
- `MergeOrderList`: 2つのボタンがあり、押すと通知する。ロック中・動画なしでは押せない

### E2E(`e2e/dateHeadings.spec.ts`)
- 撮影日時の名前の動画(`20250805_120000.mp4` 青、`20250804_090000.mp4` 赤、`20250804_180000.mp4` 緑)をこの順でアップロードし、「撮影日時の順に並べる」→「撮影日ごとに見出しを入れる」を押すと、一覧が「2025年8月4日」・赤・緑・「2025年8月5日」・青になる。もう一度押しても見出しは増えない。結合した動画の 0.5・1.5・2.5・3.5・4.5秒が 白・赤・緑・白・青(SC-001・002・003)

## 実装のレビューで変えた点

| # | 指摘 | 対応 |
|---|---|---|
| R1(P1) | 見出しを入れたあとに同じ日の早い動画を足して並べ直すと、見出しが日の途中に残り、もう一度押すと同じ日付の見出しが2つになる | 日付の見出しを「その日の見出し」として置き直す `placeDateHeadings.ts` を足し、2つのボタンの両方で使うようにした(Q5) |
| R2(P1、再レビュー) | R1 の修正で、その日の動画を全部消して残った見出しが、ボタンを押すと次の日の見出しと入れ替わる後退が入った | 見出しを入れる位置をさかのぼるとき、日付の形(「〇年〇月〇日」)の見出しはまたがないようにした |
| 要確認 | 並べるだけでも、同じ日付の見出しが1つにまとまる(項目が減る) | 仕様として認めた(並べたあとの順で最初の1つを残す)。テストを足した |

見送った P2: `useMergeQueue` の更新関数の中で見出しの id の番号を進めている(StrictMode の開発時に番号が飛ぶが、重ならないので害はない)。ファイル名に数字が多いと、最初の一致だけを見るので日付を読み違えうる(ユーザーの動画の名前の形では起きない)。見出しの文を書き換えると日付の見出しとみなされなくなる、手で入れた同じ文の見出しが1つにまとめられる(どちらも「日付と同じ文のテキストの場面を日付の見出しとみなす」という決め方の結果)。

最終ラウンド(3回目)のレビュー: P0・P1 ゼロで合格。残った P2(どれも、撮影日時の順に並べてから使う想定では起きない): 並べていない一覧で、動画のない日の見出しや手で入れた日付の形の文が日付の見出しの後ろにあると、押したときに2つの順が入れ替わる。消した日に手で入れた小見出しが残ると、次の日の見出しの後ろへ回る。
