# プラン目次: テキストの場面を動画の間に挟んで結合する

元資料: `docs/requirements/text-merge.md`(結合そのものの要件は `docs/requirements/video-merge.md`)

1つのプランには大きすぎるため、単体で動作確認できる2つのプランに分ける。上から順に実装する(プラン2はプラン1の API に依存する)。

| 順 | プラン | 範囲 | 主な要件 |
|---|---|---|---|
| 1 | [text-merge-backend.md](text-merge-backend.md) | フォントの導入、テキストの正規化と検証、文字の描画、テキストの場面の中間ファイル、結合 API の `items` 化、結合テスト | FR-002〜010、FR-013、FR-014(サーバー側)、SC-001〜SC-005a・SC-007・SC-009 のサーバー側 |
| 2 | [text-merge-ui.md](text-merge-ui.md) | 結合リストのテキストの場面への対応、挿入・編集・削除・並べ替えの画面、画面側の検証、合計の長さ、通しの E2E | FR-001、FR-004・004a・007・008・011〜014(画面側)、ストーリー1〜3の受け入れシナリオ、SC-001〜SC-008 の画面側 |

各プランは「概要、背景、詳細設計、テスト影響範囲、新規テストケース、実装順、コミット前テスト実行、スコープ外」の8項目で書く。

## 事前タスク(反映済み)

質問への回答のうち要件に関わるもの(Q1・Q2・Q5〜Q7)は、`docs/requirements/text-merge.md` に反映した(FR-004 の1行20文字と正規化、FR-004a、FR-006 の文字の大きさ、SC-004・SC-005・SC-005a、既知の制限)。

## 共通の決定事項(質問 Q1〜Q19 の回答。すべて推奨案)

| # | 論点 | 決定 |
|---|---|---|
| Q1 | 「縮めない」と「必ず収まる」の食い違い | 1行20文字まで(5行・全体100文字)とし、文字の大きさは出力の短い辺から決める。テキストの長さでは変えない |
| Q2 | 小さい出力 | 文字の大きさに下限は設けない。既知の制限として要件に書いた |
| Q3 | 描く方式 | Pillow で出力サイズの PNG を描き、FFmpeg で指定の長さの映像にする。利用者の文字を FFmpeg のフィルター文字列に入れない |
| Q4 | フォント | IPAexゴシック(`fonts-ipaexfont-gothic`)を backend のイメージに入れる。パスは環境変数 `SCENE_FONT_PATH` で変えられ、ファイルがなければ起動時に失敗する |
| Q5 | フォントにない文字 | 拒否する。判定はサーバーがフォントの文字の表(cmap)で行い、422 で原因の文字を返す |
| Q6 | 制御文字・空白 | 改行以外の制御文字(タブを含む)は拒否する。`\r\n` は `\n` にそろえる。前後の空白と先頭・末尾の空行を取り除いてから数える。途中の空行は1行として数え、表示する |
| Q7 | 1文字の数え方 | NFC で正規化したあとのコードポイント数。画面は `[...text].length` で同じ数え方にする |
| Q8 | 結合の依頼の形 | `video_ids` をやめ、`items: [{type:"video", video_id}, {type:"text", text, duration_tenths}]` にする。表示時間は0.1秒単位の整数 |
| Q9 | テキストの場面の数 | 個数の上限は設けない(30分の上限で実質1800個まで)。依頼の本文は1MBまで |
| Q10 | ログ | テキストの本文は記録しない。文字数・行数・リスト内の番号だけを記録する |
| Q11 | 失敗の文言 | 「3番目のテキストの場面の作成に失敗しました」。番号はリスト全体での位置 |
| Q12 | 追加する場所 | 各行に「この後にテキストを挿入」、リストの先頭に「先頭にテキストを挿入」のボタン |
| Q13 | 入力と編集 | 行の中にその場で入力欄(複数行の欄と秒数の欄)を出し、「確定」「取り消し」で閉じる。確定するまでリストに入れない |
| Q14 | 編集中・結合中 | 結合中はテキストの追加・編集・削除・並べ替えをすべて無効にする。確定していない編集がある間は結合ボタンを押せない |
| Q15 | 見せ方 | 「📝 {1行目}(3.0秒)」。2行以上なら1行目の後に「…」。ラベルは「テキストの場面: {1行目}」 |
| Q16 | 「読める」ことの確かめ方 | 画素で確かめる(四隅が黒、中央に白、白い画素が余白の内側)。Pillow の描画は単体テストで確かめる。最終的に読めるかは人が手動で確かめる |
| Q17 | 長さの許容 | テキストの場面の長さはフレーム数に丸める。テストでは「±1フレーム + AAC の分(0.03秒)」を許容し、これが0.1秒以内であることを確かめる |
| Q18 | プランの分け方 | この目次と2つのプラン |
| Q19 | モデルの割り当て | video-merge と同じ(下の「全プラン共通の進め方」) |

## プランのレビューで決まった事項

4つの観点(設計整合性、セキュリティ、運用、ビジネス整合性)のレビューのうち、P1 のすべてと P2 の B-8・B-9 を反映した。ほかの P2 と要確認は反映していない。

| # | 観点 | 指摘 | 決定 | 反映先 |
|---|---|---|---|---|
| D-1 | 設計 | テキストの場面を検証して入力の列にする処理の置き場所がない | 純粋関数 `normalize_text_items.py`(番号付きの失敗)と `build_merge_segments.py` を足し、`start_merge` は呼ぶだけにする | backend |
| D-2 | 設計 | API の `items` への変換の置き場所が食い違う | 変換は `requestMerge.ts` の中だけで行う。`useMergeQueue` は API の形を返さない | backend・ui |
| D-3 | 設計 | `useMergeQueue` に計算と変換が残る | `sumMergeItemsMilliseconds`、`replaceItem`、`countVideoItems` を純粋関数にする | ui |
| S-1/O-3 | セキュリティ・運用 | 422 で返す経路で本文がログに残らないかが決まっていない | 413・422 は記録しない。`ValidationError` の入力値と原因の文字を含む message をログに渡さない。配置の `ValueError` のメッセージに行の中身を入れない。422・413 の各経路のあとで本文がログにないことを結合テストで確かめる | backend |
| O-1 | 運用 | フォントの読み込みの失敗の記録がない | error で `err` と `setting="SCENE_FONT_PATH"` を記録してから再送出する。パスの値は記録しない | backend |
| O-2 | 運用 | テキストの場面の失敗ログに `err` と段階がない | `err`、`failed_step`(layout・render・encode)、出力の幅・高さを必ず出す | backend |
| B-1 | ビジネス | 文頭・文末のタブがすり抜ける。画面とサーバーで取り除く文字が違う | 制御文字の判定を取り除く処理より前に置く。取り除くのは半角空白・全角空白・改行だけ(`strip()`・`trim()` を使わない) | backend・ui |
| B-2 | ビジネス | 絵文字が画面で拒否されない | 画面でも `\p{Emoji_Presentation}` と U+FE0F を確定の時点で拒否する。ほかのフォントにない文字は引き続きサーバーが判定する | ui |
| B-3 | ビジネス | 挿入の位置を番号で持ち、入力中の並べ替えでずれる | 位置を直前の項目の id で持ち、入力中は並べ替えと削除も無効にする | ui |
| B-8 | ビジネス(P2) | 画面とサーバーで理由の文言が違う | 表示時間は「表示時間は1秒から60秒までで、小数第1位まで指定してください」にそろえる。超過の時間はどちらも秒に切り上げる(もともと同じ関数の書式で、テストの書き方を直した) | backend・ui |
| B-9 | ビジネス(P2) | 小さい出力で、受け付けたあとに失敗する | 出力の短い辺が23ピクセル未満なら、受け付ける前に 422 `output_too_small_for_text` を返す。要件定義の FR-006 と既知の制限に書き足した | backend・要件 |

## 全プラン共通の進め方

- 実装は `tdd` スキルで行う(テストリストから1件ずつ、Red → Green → Refactor)
- 各タスクの終わりにコミットする。プランの完了時に `.claude/rules/review.md` の手順でレビューする
- モデルの割り当て
  - **メインセッション(Opus)**: 描画と文字の配置、FFmpeg の引数、API の形とジョブの流れ、E2E、サブエージェントの成果の統合
  - **Sonnet のサブエージェント**(`general-purpose`、`model: sonnet`): 仕様とテストケースがプランで確定している画面・純粋関数のタスク
  - **Haiku のサブエージェント**(`general-purpose`、`model: haiku`): フォントの導入、テストの補助関数など、入出力が決まった定型作業
  - **レビュー**: `design-reviewer`(プランとの照合)、`edge-case-reviewer`(境界・異常系)、`security-reviewer`(セキュリティ。Bash を持たないため差分を渡す)を並列に実行する
- P0・P1 を直したら、再レビューに戻す
- 実装中にプランにない変更が必要になったら、この目次に「実装で追加・変更した点」の表を作って記録する

## 実装で追加・変更した点(プラン1)

| # | 変更 | 理由 |
|---|---|---|
| I-1 | フレーム数の計算を `text_scene_duration.py` に、本文の形の確認を `parse_merge_request.py` に切り出した。配置の関数から文字の大きさだけを返す `text_scene_font_size` と、配置の失敗を表す `TextSceneLayoutError` を足した。フォントは `SceneFont`(パスと文字の集合)で持つ | 1ファイル1責務。フレーム数はジョブの進み具合・時間の上限・長さの判定でも使う。描画は「文字の大きさ → 行の幅を測る → 配置」の順になる。`failed_step` の layout と render を見分ける |
| I-2 | 「結合の開始のログに `text_scene_count`」は入れず、完了・失敗のログだけにした | 開始のログはもともとない。logging.md 規則5の info の対象に「開始」は入らない(実装レビュー D-2) |
| I-3 | `build_text_scene_args` は `TextScene` ではなく、フレーム数と秒数を受け取る。「本文が引数に入らない」はテストではなく関数の形で保証し、引数の全体を固定の期待値で確かめる | 引数を組み立てる関数にテキストを渡さなければ、テキストが届く経路がなくなる |
| I-4 | テキストの場面の結合テストは、既存の `test_merge_api.py` ではなく新しい `test_text_merge_api.py` に置いた | 既存テストの本文の書き換え(タスク7)と同時に進めるため。ファイルが大きくなりすぎないため |
| I-5 | スキーマに `extra="forbid"` を付け、`text` を `StrictStr` にした | 古い形(`video_ids`)や余計なキーを確実に 422 にする |
| I-6 | 合計の長さの判定で、テキストの場面はフレーム数に丸めた長さと指定の長さの長い方で数える | 実装レビュー(異常系 P1)。出力の fps が低いと、丸めで長くなり、指定の長さだけで数えると30分を超える出力ができた。画面は fps を知らないため、丸めで長くなるときだけサーバーの判定が画面より厳しくなる |
| I-7 | 既知の制限: 出力の fps が5未満だと、テキストの場面の長さの誤差が0.1秒を超えることがある(SC-003) | フレーム単位でしか長さを決められず、丸めの誤差は最大で半フレームになるため。通常の動画(24fps以上)では起きない |
| I-8 | フォントを開く・解析するときの例外は、設定の名前と例外の型だけの文言に置き換えてから記録する | 実装レビュー(セキュリティ P2)。OSError の文言にはパスが入る。コンテナは root で動くため、権限で開けない経路はテストで再現できない |
| I-9 | 画像の入力に `-pattern_type none` を付けた | 実装レビュー(セキュリティ P2)。保存先のパスに `%` があっても連番の書式として解釈させない |
| I-10 | 単体テストを足した: 本文の上限の境界(`test_read_limited_body.py`)。結合テストを強めた: 日本語の字形がフォントにない文字の四角と異なること、記号入りの本文が描画まで通ること | 実装レビュー(異常系 P1、設計 P1、セキュリティ P2) |
| I-11 | `start_merge`・`run_merge_job` は API の切り替えと同時に書き換えたため、テキストの場面の結合テストは Red を確かめられなかった。代わりに、文字の色を黒にする・失敗ログに本文を入れる、の2つのミューテーションでテストが落ちることを確かめた | tdd の手順から外れた点の記録 |
