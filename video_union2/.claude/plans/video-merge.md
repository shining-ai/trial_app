# プラン目次: 動画の結合機能

元資料: `docs/requirements/video-merge.md`

1つのプランには大きすぎるため、単体で動作確認できる3つのプランに分ける。上から順に実装する(後のプランは前のプランの成果に依存する)。

| 順 | プラン | 範囲 | 主な要件 |
|---|---|---|---|
| 1 | [upload.md](upload.md) | 共通基盤(設定・ログ・子プロセス・保存先・エラー)、アップロードAPI、アップロード画面 | FR-001、FR-008(サイズ・解像度)、FR-009(サイズ・解像度)、FR-013 |
| 2 | [merge.md](merge.md) | 結合ジョブ(2段階エンコード)、進み具合、ダウンロードAPI | FR-003〜007、FR-008(本数・長さ)、FR-009(サーバー側)、FR-010〜012 |
| 3 | [merge-ui.md](merge-ui.md) | 並べ替え、合計の長さ、結合・進み具合・ダウンロードの画面、通しのE2E | FR-002、FR-004、FR-009(画面側) |

各プランは「概要、背景、詳細設計、テスト影響範囲、新規テストケース、実装順、コミット前テスト実行、スコープ外」の8項目で書く。

## 事前タスク(プラン1の実装前に行う)

質問への回答で決まった内容を、元資料とルールに反映する。プランだけに書くと、レビューアーが照合する元資料と食い違うため。

- `docs/requirements/video-merge.md` に追記する
  - 解像度の判定と出力サイズの計算は、回転情報を反映した表示サイズで行う(FR-006、FR-008 の注記)
  - 結合できるのは2本以上。同じ動画IDの重複指定は受け付けない
  - 「30分まで」は1800.000秒ちょうどを含む。各動画の長さは映像の長さで数える
  - 結合はジョブとして非同期に行い、進み具合を表示する。同時に実行できる結合は1件
  - 途中の1本で失敗したら結合全体を失敗にし、何番目のどのファイルかを知らせる
  - 結合前に空き容量を確かめ、足りなければ断る(HTTP 507)
  - ファイルを消す時点(下の決定事項 Q6)
  - ダウンロードのファイル名は `merged-YYYYMMDD-HHMMSS.mp4`
  - 既知の制限とスコープ外: HDR・10bit動画は色が褪せる、非正方形画素は1:1として扱う、サムネイル・プレビューは扱わない、再読み込みで一覧は消える
- `.claude/rules/testing.md` の「テスト用の動画」を書き換える
  - テスト用の動画は、テストのたびにFFmpegの `testsrc` や単色の映像で作る
  - 作れないもの(拡張子だけ動画のテキストファイルなど)だけを `backend/tests/fixtures/` に置く
- 担当: メインセッション(Opus)。ドキュメントの変更なので、ユーザーの確認を経てコミットする

## 共通の決定事項(質問 Q1〜Q25 の回答。すべて推奨案)

| # | 論点 | 決定 |
|---|---|---|
| Q1 | 結合の処理方式 | ジョブ方式。`POST /api/merges` は202とジョブIDを返し、`GET /api/merges/{id}` で進み具合を問い合わせる。状態はメモリに持つ(再起動で消える) |
| Q2 | FFmpegの実行方法 | 2段階。1本ずつ同じ形式の中間ファイルに揃え、最後に再エンコードなしでつなぐ |
| Q3 | エンコード設定 | `preset veryfast`・`CRF 20` を既定値にし、環境変数で変えられるようにする。GPUは使わない。長時間かかることは許容する |
| Q4 | 同時実行 | 1件だけ。実行中の新しい結合は409 |
| Q5 | ディスク | 上限は暫定値のまま。結合前に空き容量を確かめ、足りなければ507 |
| Q6 | ファイルを消す時点 | 中間ファイルは結合の終了時(成功・失敗とも)。アップロード動画は一覧から外したとき。結合結果は次の結合を始めるとき。起動時に24時間より古いものを消す |
| Q7 | 再読み込み | 一覧は消えてよい |
| Q8 | アップロードの方式 | 本文にファイルをそのまま送る(`application/octet-stream`)。受信しながらバイト数を数え、4GBを超えたら打ち切る |
| Q9 | アップロードの表示 | 1ファイルごとに進み具合を表示する。同時に送るのは2本まで |
| Q10 | 回転情報 | 回転後の表示サイズで判定・計算する |
| Q11 | HDR・10bit | スコープ外。既知の制限として記録する |
| Q12 | 複数の映像・音声 | 最初の映像と最初の音声を使う。音声はステレオにまとめる |
| Q13 | 30分の数え方 | 1800.000秒を含む。映像の長さで数え、音声は映像の長さに合わせて切る・無音で埋める。出力の±1フレームのずれは許容 |
| Q14 | 最少本数 | 2本以上 |
| Q15 | 同じIDの重複 | 受け付けない(422) |
| Q16 | 途中の1本の失敗 | 全体を失敗にし、何番目のどのファイルかを知らせる |
| Q17 | 非正方形画素 | スコープ外。1:1として扱う |
| Q18 | 並べ替えの操作 | 「上へ」「下へ」「先頭へ」「末尾へ」のボタン。ドラッグ&ドロップは扱わない |
| Q19 | サムネイル・プレビュー | スコープ外 |
| Q20 | ファイル名 | `merged-YYYYMMDD-HHMMSS.mp4` |
| Q21 | テスト用の動画 | テストのたびにFFmpegで作る |
| Q22 | 上限のテスト | 上限を環境変数で設定できるようにし、テストでは小さい値にする。判定の純粋関数は本当の値でも単体テストする |
| Q23 | 結合結果の検証 | 単色の動画を結合し、フレームのピクセルの色で並び順・中央配置・黒い縁を確かめる。長さ・解像度・fps・音声はffprobeで確かめる |
| Q24 | プランの分け方 | 3つに分ける(上の表) |
| Q25 | モデルの割り当て | Opus: FFmpeg・ジョブ・設計判断・レビュー。Sonnet: 仕様が明確な画面と配線。Haiku: 定型作業。レビューは既存の3エージェント |

## 全プラン共通の進め方

- 実装は `tdd` スキルで行う(テストリストから1件ずつ、Red → Green → Refactor)
- 各タスクの終わりにコミットする。プランの完了時に `.claude/rules/review.md` の手順でレビューする
- モデルの割り当て
  - **メインセッション(Opus)**: FFmpeg の引数・ジョブ・設計判断を含むタスク、サブエージェントの成果の統合
  - **Sonnet のサブエージェント**(`general-purpose`、`model: sonnet`): 仕様とテストケースがプランで確定している画面・配線のタスク
  - **Haiku のサブエージェント**(`general-purpose`、`model: haiku`): テスト用動画を作る補助関数など、入出力が決まった定型作業
  - **レビュー**: `design-reviewer`(プランとの照合)、`edge-case-reviewer`(境界・異常系)、`security-reviewer`(セキュリティ。Bash を持たないため差分を渡す)を並列に実行する
- P0・P1 を直したら、再レビューに戻す
