# プラン目次: 動画の結合機能

元資料: `docs/requirements/video-merge.md`

1つのプランには大きすぎるため、単体で動作確認できる3つのプランに分ける。上から順に実装する(後のプランは前のプランの成果に依存する)。

| 順 | プラン | 範囲 | 主な要件 |
|---|---|---|---|
| 1 | [upload.md](upload.md) | 共通基盤(設定・ログ・子プロセス・保存先・エラー)、アップロードAPI、アップロード画面 | FR-001、FR-008(サイズ・解像度)、FR-009(サイズ・解像度・本数の画面側)、FR-013、FR-015(アップロード動画・起動時の掃除) |
| 2 | [merge.md](merge.md) | 結合ジョブ(2段階エンコード)、進み具合、ダウンロードAPI | FR-003〜007、FR-008(本数・長さ)、FR-009(サーバー側)、FR-010〜012、FR-014、FR-015(中間ファイル・結合結果)、FR-016 |
| 3 | [merge-ui.md](merge-ui.md) | 並べ替え、合計の長さ、結合・進み具合・ダウンロードの画面、通しのE2E | FR-002、FR-004、FR-009(画面側)、FR-014(進み具合の表示)、FR-015(リストから外したときの削除)、SC-001、SC-002 |

各プランは「概要、背景、詳細設計、テスト影響範囲、新規テストケース、実装順、コミット前テスト実行、スコープ外」の8項目で書く。

## 事前タスク(反映済み)

質問への回答で決まった内容は、`docs/requirements/video-merge.md`(FR-006・008・013 の注記、FR-014〜016、前提とスコープ外)と `.claude/rules/testing.md`(テスト用の動画の作り方)に反映済み(`ae36a51`)。プランのレビューで決まった入れ物の形式の許可リスト(R1)は、FR-013 に追記した。

## 共通の決定事項(質問 Q1〜Q25 の回答。すべて推奨案)

| # | 論点 | 決定 |
|---|---|---|
| Q1 | 結合の処理方式 | ジョブ方式。`POST /api/merges` は202とジョブIDを返し、`GET /api/merges/{id}` で進み具合を問い合わせる。状態はメモリに持つ(再起動で消える) |
| Q2 | FFmpegの実行方法 | 2段階。1本ずつ同じ形式の中間ファイルに揃え、最後に再エンコードなしでつなぐ |
| Q3 | エンコード設定 | `preset veryfast`・`CRF 20` を既定値にし、環境変数で変えられるようにする。GPUは使わない。長時間かかることは許容する |
| Q4 | 同時実行 | 1件だけ。実行中の新しい結合は409 |
| Q5 | ディスク | 上限は暫定値のまま。結合前に空き容量を確かめ、足りなければ507 |
| Q6 | ファイルを消す時点 | 中間ファイルは結合の終了時(成功・失敗とも)。アップロード動画は一覧から外したとき。結合結果は次の結合を始めるとき。起動時に24時間より古いものを消す |
| Q7 | 再読み込み | 一覧は消えてよい |
| Q8 | アップロードの方式 | 本文にファイルをそのまま送る(`application/octet-stream`)。受信しながらバイト数を数え、4GBを超えたら打ち切る |
| Q9 | アップロードの表示 | 1ファイルごとに進み具合を表示する。同時に送るのは2本まで |
| Q10 | 回転情報 | 回転後の表示サイズで判定・計算する |
| Q11 | HDR・10bit | スコープ外。既知の制限として記録する |
| Q12 | 複数の映像・音声 | 最初の映像と最初の音声を使う。音声はステレオにまとめる |
| Q13 | 30分の数え方 | 1800.000秒を含む。映像の長さで数え、音声は映像の長さに合わせて切る・無音で埋める。出力の±1フレームのずれは許容 |
| Q14 | 最少本数 | 2本以上 |
| Q15 | 同じIDの重複 | 受け付けない(422) |
| Q16 | 途中の1本の失敗 | 全体を失敗にし、何番目のどのファイルかを知らせる |
| Q17 | 非正方形画素 | スコープ外。1:1として扱う |
| Q18 | 並べ替えの操作 | 「上へ」「下へ」「先頭へ」「末尾へ」のボタン。ドラッグ&ドロップは扱わない |
| Q19 | サムネイル・プレビュー | スコープ外 |
| Q20 | ファイル名 | `merged-YYYYMMDD-HHMMSS.mp4` |
| Q21 | テスト用の動画 | テストのたびにFFmpegで作る |
| Q22 | 上限のテスト | 上限を環境変数で設定できるようにし、テストでは小さい値にする。判定の純粋関数は本当の値でも単体テストする |
| Q23 | 結合結果の検証 | 単色の動画を結合し、フレームのピクセルの色で並び順・中央配置・黒い縁を確かめる。長さ・解像度・fps・音声はffprobeで確かめる |
| Q24 | プランの分け方 | 3つに分ける(上の表) |
| Q25 | モデルの割り当て | Opus: FFmpeg・ジョブ・設計判断・レビュー。Sonnet: 仕様が明確な画面と配線。Haiku: 定型作業。レビューは既存の3エージェント |

## プランのレビューで決まった事項

4つの観点(設計整合性、セキュリティ、運用、ビジネス整合性)のレビューの指摘を受けて決めた事項。

| # | 論点 | 決定 |
|---|---|---|
| R1 | FFmpeg・ffprobe に渡す入力 | `-protocol_whitelist file` と入れ物の形式の許可リスト(MP4・MOV、MKV・WebM、AVI、MPEG-TS・PS、WMV、FLV)を付ける。判定も許可リストで行い、再生リスト・画像・GIF は「動画として読み込めませんでした」で拒否する。2段目の concat にも `-protocol_whitelist file` を付け、一覧のパスが中間ファイルのフォルダ内にあることを確かめる |
| R2 | 長さの申告値のすり抜け | 1段目に `-t {長さ}` を付け、ffprobe・ffmpeg に時間の上限を設ける |
| R3 | 子プロセスの実行 | FFmpeg・ffprobe はすべて `lib/run_process.py` で実行する。標準出力を1行ずつ渡すコールバックと時間の上限を持たせる。成功の info は ffmpeg の成功と1秒を超えた ffprobe だけ、`run_process.py` で記録する |
| R4 | 保存先のパス | すべて `lib/disk_storage.py` の種類ごとの関数で作る。merge の純粋関数はパスを引数で受け取る |
| R5 | 機能の境界 | `VideoInfo` とメタ情報の書き込みは upload に置く。merge はメタ情報ファイル(取り決めた JSON 形式)を自分の型 `MergeSource` で読む。ジョブの状態(`merge_job_store.py`)は merge に置く(Q24 後の決定「lib に置く」を改める)。download はジョブの状態を参照せず、結果ファイルの有無と更新時刻だけで判断する(成功時にだけ `result.partial.mp4` を `result.mp4` に改名する) |
| R6 | ログと失敗の扱い | request_id は contextvars で持ち、ジョブにも引き継ぐ。起動時の処理は `startup`。ジョブの失敗・後片付けの失敗・起動時の掃除の失敗は、error で記録してから再送出する(後始末の失敗は元の例外に添える)。ジョブのタスクには例外を受け取るコールバックを付ける。ログに元のファイル名は出さない |
| R7 | 画面とサーバーの文言 | エラーの message はサーバーが決め、画面はそのまま表示する。動画でないときは「動画として読み込めませんでした」。超過の時間は秒を切り上げて「{m}分{s}秒」で、画面とサーバーで同じ書式にする。解像度の上限は縦長なら 2160x3840 と表示する |
| R8 | 要件にない振る舞いの削除 | アップロード時の空き容量の確認(507)、アップロード中は結合できない制約、並べ替えでダウンロードリンクを消す動きは入れない |
| R9 | 本数の枠 | 残りの枠は「100 − 結合リスト − 送信中 − 待機中」で数える |
| R10 | 成功基準の確認 | E2E で、画面で並べ替えた順にフレームの色が並ぶことと、最後までデコードできることを確かめる。進み具合の表示は単体テストで確かめ、E2E では必須にしない |

## 全プラン共通の進め方

- 実装は `tdd` スキルで行う(テストリストから1件ずつ、Red → Green → Refactor)
- 各タスクの終わりにコミットする。プランの完了時に `.claude/rules/review.md` の手順でレビューする
- モデルの割り当て
  - **メインセッション(Opus)**: FFmpeg の引数・ジョブ・設計判断を含むタスク、サブエージェントの成果の統合
  - **Sonnet のサブエージェント**(`general-purpose`、`model: sonnet`): 仕様とテストケースがプランで確定している画面・配線のタスク
  - **Haiku のサブエージェント**(`general-purpose`、`model: haiku`): テスト用動画を作る補助関数など、入出力が決まった定型作業
  - **レビュー**: `design-reviewer`(プランとの照合)、`edge-case-reviewer`(境界・異常系)、`security-reviewer`(セキュリティ。Bash を持たないため差分を渡す)を並列に実行する
- P0・P1 を直したら、再レビューに戻す

## 実装で追加・変更した点(Step 4)

実装中に、プランにない変更が必要になったもの。経緯と理由は [video-merge.log.md](video-merge.log.md) に記録する。

| # | 変更 | 理由 |
|---|---|---|
| I1 | 入力の許可リストと制限の引数を `backend/app/lib/media_input_policy.py` に置き、upload の ffprobe と merge の ffmpeg の両方から使う | 同じ許可リストを2つの機能で持つと食い違う。FFmpeg に渡す入力の制限は特定の機能に属さない基盤(architecture.md の問い2)と判断した |
| I2 | `disk_storage.py` は関数ではなく `DiskStorage` クラスのメソッドにし、`merge_parts_dir` を足した | 保存先のルートを設定から受け取るため。中間ファイルのフォルダを `build_concat_list` の確認と後片付けで使う |
| I3 | 応答のヘッダーに `X-Request-ID` を付ける | 結合ジョブのログの request_id を、`POST /api/merges` と突き合わせて確かめるため(R6 のテスト) |
| I4 | `MergeRequest` では ID の形式を制約せず、`load_merge_sources` で形式と存在を確かめて `video_not_found`(422)にする | 形式の誤りも存在しない ID も、利用者には同じ「指定された動画が見つかりません」で返すため。リクエストの形の誤り(`video_ids` がないなど)は共通の形の `invalid_request`(422)にする |
| I5 | `load_merge_sources` は、メタ情報に加えて動画ファイルがあることも確かめる | メタ情報だけ残った状態で結合を始めないため |
| I6 | ffprobe 自体が失敗したファイル(許可リストにない形式など)は `not_a_video`(422)にする | ffprobe が読めないファイルは動画として扱えないため |
| I7 | 映像ストリームのうち、カバー画像(`attached_pic`)は「最初の映像」として扱わない | MP4・MKV のカバー画像は静止画で、これを映像として使うと結合が壊れるため |
| I8 | `avg_frame_rate` が `0/0` のときは `r_frame_rate` を使う | 一部の動画で平均フレームレートが取れないため |
| I9 | 結合ジョブが失敗したときは、元の例外をそのまま再送出し、失敗した番号はジョブの中で数える | R6「元の例外を再送出」を守るため(番号を運ぶために例外を包まない) |
| I10 | 起動時の掃除は、`merges/` の古いジョブのフォルダも中身ごと消す | 結合結果も24時間で消す対象(FR-015)のため |
| I11 | frontend の `formatDuration` は `frontend/src/lib/` に置いた | upload の `UploadList` でも使い、2つ目の利用が出たため(プランの判断基準どおり) |
| I12 | E2E は `workers: 1` で順に実行し、並び順を確かめるテストは1本ずつアップロードする | 結合は同時に1件しか実行できない(409)。アップロードは2本ずつ並行し、完了した順にリストへ入るため |
| I13 | `run_process` は、取り消しやその他の例外でも子プロセスを止め、標準出力を行の長さの上限なしで読む | 実装レビュー(異常系)。`--reload` の再起動などで FFmpeg が残り続けるのと、64KiB を超える行(長いメタデータのタグ)で 500 になるのを防ぐ |
| I14 | メタ情報に `video_stream_index`・`audio_stream_index`(ストリームの絶対番号)を足し、1段目は `[0:{番号}]` で選ぶ。形式の `version` は未公開のため1のまま | 実装レビュー(異常系)。判定はカバー画像を除いた映像で行っているのに、`0:v:0` ではカバー画像を選ぶことがある |
| I15 | Matroska・WebM の映像の長さは `tags.DURATION` から読む | 実装レビュー(異常系)。ストリームの duration がなく、音声のほうが長いと FR-008(映像の長さで数える)に反した |
| I16 | 1段目に `-xerror` を付ける | 途中で切れた動画を、FFmpeg はエラーを出しながら終了コード0で短い出力にしてしまう(実際に確かめた)。merge.md の「途中を切り詰めたファイルで failed」を満たすため |
| I17 | 結合の依頼は、メタ情報を読む前に ID の本数と重複を確かめる(`validate_video_ids`) | 実装レビュー(セキュリティ)。同じ ID を大量に並べた依頼で、件数分の読み込みをさせない |
| I18 | 結合前の空き容量の判定に、開始時に消す前回の結果の大きさを足す | 実装レビュー(異常系)。前回の結果を消せば足りるのに 507 になっていた |
| I19 | アップロードは、受信の前に `Content-Length` を確かめ、上限超過なら413、空き容量より大きければ507を返す(R8 のうち「アップロード時の空き容量の確認は入れない」を改める) | 実装レビュー(セキュリティ P1)。アップロードを重ねて保存先を使い切らせない。要件はアップロード時の507を禁じていないため、要件との矛盾はないと判断した |
| I20 | アップロードの判定で、長さが有限でない(NaN・inf)、fps・幅・高さが0の動画を「動画として読み込めませんでした」にする。回転タグの小数(`"90.0"`)も読む | 実装レビュー(セキュリティ P2・異常系 P2)。上限の判定のすり抜けと 500 を防ぐ |
| I21 | メタ情報の一時ファイルのパスも `disk_storage.upload_metadata_temp_path` で作り、失敗時の後片付けの対象に入れる | 実装レビュー(設計 P0)。R4 に反してファイル名を連結していた |
| I22 | frontend: 状態の問い合わせが通信の失敗・5xx なら問い合わせを続け、404 のときだけ失敗にする。削除が 404(`video_not_found`)なら一覧から外す。アップロードの中断・時間切れ・JSON でない応答でも項目を失敗にする。失敗で message がないときは「結合に失敗しました」を出す | 実装レビュー(異常系 P1・P2)。一時的な失敗でジョブを見失う、消えた動画を一覧から外せない、項目が送信中のまま残る、を防ぐ |
| I23 | テストの値: 結合テストの解像度の超過は 642x360(641 の境界は単体テスト)。長さの許容は「±1フレーム」に音声(AAC)のフレームの分として 0.01〜0.03 秒を足す | H.264(yuv420p)は奇数の幅の動画を作れない。AAC はフレーム単位(約 0.021 秒)で長さが決まるため |
